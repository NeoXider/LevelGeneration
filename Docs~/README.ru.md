# Neoxider LevelGeneration

Reusable библиотека генерации уровней, door/socket snapping, authoring tools и runtime minimap primitives.

Пакет лежит в:

```text
Assets/ThirdParty/Neoxider/LevelGeneration
```

Проектная интеграция RedoSchool лежит отдельно:

```text
Assets/_source/Scripts/Epics/World
```

## Что находится в библиотеке

- Чистые domain/application модели генератора.
- Layout Pacing V2 core: pacing config, content plan, graph planning, branch planning, retry degradation, diagnostics.
- Room selection и socket placement без зависимости от MissionMap/Quiz/Cheats.
- Unity-facing descriptors: `RoomTemplate`, `DoorSocket`, `TilesetSO`, `RoomDatabase`.
- Editor tools для room authoring, compatibility reports и door snapping.
- Runtime primitives для minimap, room instance, endpoint/room-enter events и transition helpers.

## Подключение к игре

Пакет не ссылается на сборки игры (страж `LevelGenerationIndependenceTests`). Что карте уровня нужно знать
об игре, игра передаёт сама при запуске (после `RuntimeInitializeLoadType.SubsystemRegistration`, где пакет
сбрасывает прошлую сессию):

- `MinimapGameplay.Context = <IMinimapGameplayContext>` — где ученик (`RouteHintPresence`), занята ли
  клавиатура интерфейсом, строка состояния управления для диагностики подсказки маршрута;
- `LevelGenerationRuntimeLog.InfoSink` / `WarnSink` — журнал игры; приёмник получает файл и метод вызова.

Без этого карта работает автономно: ученик всегда в мире, клавиатура свободна, журнал — консоль Unity.

Раскладку контента в редакторе проект задаёт через `LevelGenerationProjectPaths` (обычно из `[InitializeOnLoad]`
своей редакторной сборки): `RoomPrefabRoots` — где редакторный `RoomDatabase` ищет префабы комнат (по умолчанию
весь `Assets`), `RoomPrefabFolder` — папка Room Authoring Toolkit, `DefaultRoomPoolPath` — пул комнат для
инструментов (пусто — не задан). `TilesetCatalog` в редакторе ищет `TilesetSO` по всему проекту. В плеере эти
пути не используются.

Визуальный PlayMode-страж миникарты меняет реальный GameView и снимает normal/narrow screenshots,
поэтому запускается только из интерактивного Unity Test Runner. В batchmode он честно помечается
`Ignored`: там `WaitForEndOfFrame` не вызывается. Геометрические свойства масштаба остаются покрыты
детерминированными EditMode-тестами.

## Что не должно попадать в библиотеку

- MissionMap, Quiz, Cheats, Rewards, CoreAI/VContainer glue.
- SciFiAcademy content JSON/assets.
- RedoSchool gameplay modules и конкретные room rewards.
- Правила конкретной миссии, которые зависят от учебного контента.

## Assemblies

- `RedoSchool.LevelGeneration.Domain` - pure C# domain models/enums/events, `noEngineReferences=true`.
- `RedoSchool.LevelGeneration` - pure C# generator application services, `noEngineReferences=true`.
- `RedoSchool.LevelGeneration.Unity` - Unity prefab descriptors, ScriptableObject data и room-template authoring components.
- `RedoSchool.LevelGeneration.Runtime.Domain` - pure C# runtime-события комнат, дверей и endpoint, `noEngineReferences=true`.
- `RedoSchool.LevelGeneration.Runtime` - reusable runtime minimap, room instance, room-enter/endpoint events и transition helpers. Сборки игры не нужны: ввод и журнал подключает потребитель (раздел «Подключение к игре»).
- `RedoSchool.LevelGeneration.Editor` - reusable editor tools для authoring, door snapping и compatibility checks.

## Текущий production path

RedoSchool runtime/preview вызывает `MissionGenerator`. Если в `MissionConfigSO` включен Layout Pacing V2, генератор строит pacing graph, выбирает комнаты, размещает их через socket snapping, соединяет двери и возвращает layout diagnostics. V1 graph builder остается rollback path.

В pacing mode старые `TotalRoomsRange`/main/branch ranges являются legacy/cap data, а не exact target-count. Темп задается через Layout Pacing config и optional JSON override.

## Runtime minimap

`LevelMinimapController` остаётся IMGUI-оверлеем для совместимости с текущим runtime HUD. Обе карты —
угловая и большая — показывают только пройденные комнаты. Это единый no-spoiler-контракт для всего
содержимого: рисуются лишь связи между уже раскрытыми комнатами, а маркер выхода и колбы-фрагменты
появляются только после раскрытия своей комнаты. Большая карта раньше показывала уровень целиком, и
ученик сразу видел выход, тупики и длину оставшегося пути; теперь она отличается от угловой тем,
что вписывает весь уже пройденный маршрут с полями (`FullMapFitMarginMeters`) и центрируется на нём,
но не раскрывает будущий путь. Мелкую карту кламп не раздувает сильнее утроенного масштаба угловой
(`FullMapMaxZoomVsCompact`).
Большая карта размещается ниже верхней полосы HUD. Размер маркера игрока рассчитывается по фактическому
масштабу проекции: его доля от размера комнаты одинакова на компактной и большой картах.

Публичные `LevelMinimapSession.GetAllRooms()` и `GetAllConnections()` возвращают сырой снимок
сгенерированного layout для диагностики и других непредставленческих потребителей. Они не являются
источником отрисовки: обе карты получают комнаты и связи через `GetVisibleRooms()` и
`GetVisibleConnections()`. Иначе один забытый слой — коридор, выход или колба — снова выдал бы скрытую
комнату.

Комнаты, связи, стены и door markers кэшируются в отдельных `RenderTexture` для compact и full-map
режимов. В обычном `OnGUI` готовая геометрия выводится одним `GUI.DrawTexture`, а поверх неё живыми
слоями рисуются маркер игрока, доступный маркер выхода и колбы-фрагменты.

Кэш перестраивается при `Bind(...)`, `RoomEnteredEvent`, раскрытии комнаты по открытой двери и один раз
по окончании её проявления, восстановлении checkpoint, изменении размера панели, проекционной позы игрока или настроек отрисовки (`SimplifiedDrawing`, door markers, цвета/alpha,
`visibleMeters`, `compactContentScale`, `rotateWithPlayer`). Простое переключение режима выбирает отдельный
compact/full-map кэш и само по себе не инвалидирует оба слоя. Для регрессий есть счётчик
`StaticMapRebuildCount`: без изменения состояния карты повторный кадр не должен увеличивать это значение.

Размер экранной карточки миникарты не управляет дальностью обзора. За проекцию её мирового содержимого
отвечает authored-поле `compactContentScale` у `LevelMinimapController`: production-значение `0.5`
показывает в прежнем viewport вдвое больше мира. Тем же множителем уменьшаются маркер игрока и маркер
цели; рамка карточки, её положение и HUD не масштабируются. Большая карта вместо фиксированного
зума вписывает показанный набор комнат и центрируется на нём (`TryCalculateFullMapFit`,
`CalculateFullMapFitMeters`); `FullMapZoomDivider` остался только базой размеров маркеров.
При изменении масштаба не правьте размеры комнат или координаты layout: это данные
мира, а не настройка представления миникарты.

Экранный прямоугольник карточки (`minimapRect`) по умолчанию прижат к левому верхнему углу. Значение
по умолчанию является production-значением: authored-экземпляра `LevelMinimapController` в проекте нет,
компонент создаёт рантайм. Меньшая сторона не произвольна — по ней считается
`CompactMapScalePixelsPerMeter`, а от зума зависит, помещается ли маркер игрока в ячейку сетки и не
теряется ли он на её фоне; коридор держит `LevelMinimapFramingTests`. Прямоугольник доступен снаружи
через read-only `MinimapRect`: карта рисуется `OnGUI` в экранных пикселях, а соседний HUD — это UI Toolkit
со своим масштабированием, поэтому отступ HUD от карты обязан измеряться, а не храниться константой.

При resume `RestoreCheckpoint(...)` возвращает подтверждённый `visited_room_ids` вместе с
completed/current rooms в `LevelMinimapSession` и инвалидирует static-map cache. У старого checkpoint
этого поля нет: неоднозначный `revealed_room_ids` отбрасывается, остаются completed/current rooms.
Телепорт не обязан пересечь `RoomEnteredEvent`, поэтому полагаться только на
trigger после загрузки нельзя: иначе компактная карта остаётся центрированной на start-room и выглядит пустой.

### Когда комната появляется на карте

Комната раскрывается при фактическом входе (`RoomEnteredEvent`) и через `roomRevealDelaySeconds` (1 с)
после того, как перед игроком открылась дверь в неё (`DoorSocket.OpenedForPlayer` →
`LevelMinimapSession.ScheduleReveal`; владелец 2026-10-14: комната за открытой дверью обязана быть видна, не
дожидаясь входа). Открытая дверь не делает комнату текущей, не засчитывает её посещённой для подсказки
маршрута и не трогает таймер её простоя: прогресс — только вход дальше по пути и задание цели.

Новая комната проявляется анимацией (`RoomRevealAnimationSeconds`): цвет вспыхивает от белого к
своему, прозрачность набирается. Пока идёт проявление, комната и её связи НЕ лежат в кэше геометрии
и рисуются живым слоем поверх него; когда анимация доиграла (`PruneFinishedRevealAnimations`), кэш
перестраивается один раз и комната попадает в него.

Вход делает комнату текущей и раскрывает её. При восстановлении нового чекпоинта карта строится из
`visited_room_ids` и текущей безопасной комнаты. Если этого поля нет, карта показывает только
подтверждённо завершённые комнаты и текущую безопасную комнату. Старое поле `revealed_room_ids`
может содержать соседей, показанных открытием двери в прежней версии; оно не возвращает их на карту.

### Подсказка маршрута

Если ученик `RouteHintIdleSeconds` (60 с) не продвигается к выходу, путь сначала проявляется светящейся
цепочкой звёздочек над полом уровня (см. «Путь подсказки на полу»), а затем обе карты одновременно
показывают бегущий пунктир (или линию с бликом — `RouteHintStyle`) от игрока к двери следующей
комнаты критического пути и пульсирующий маркер у этой двери.

- **Критический путь** — `LevelCriticalPath.Build(layout)`: BFS от старта до ближайшего выхода по
  связям `DoorConnection.IsMainPath`. У развилки-вопроса главная только дверь правильного ответа,
  поэтому тупики неправильных ответов в путь не попадают. Нет главных связей до выхода — BFS по всем.
- **Прогресс** — фактический вход в комнату пути дальше самой дальней уже посещённой,
  выполнение задания текущей цели (таймер заново, подсказка прячется до нового простоя) или завершение
  всего маршрута. Боковая комната, тупик,
  ветка неверного ответа, повторный визит и открытие любой двери таймер не трогают
  и показанную подсказку не гасят: путь просто перепланируется с новой позиции.
  Решение — `DecideRouteHintProgressUseCase` (исход `RouteHintProgress`, без состояния).
  При resume прогресс берётся из
  подтверждённого `visited_room_ids`, завершённых комнат и текущей безопасной комнаты;
  старый список раскрытых комнат не означает посещение и игнорируется;
  перепривязка того же живого уровня сохраняет посещённое.
  Решение принимает `DecideRouteHintUseCase` (без состояния), состояние и таймер держит
  `LevelRouteHintSession`. Таймер идёт по игровому времени и только пока ученик в мире —
  `IMinimapGameplayContext.Presence` от игры (в RedoSchool — `RouteHintPresenceUseCase` по полному набору
  фактов ввода: UI-лок, захват клавиатуры, поле ввода, выключенный gaze-режим, замороженный контроллер или
  выключенное движение — пауза, и подсказка на это время гаснет; решение не зависит от порядка проверок
  первого блокера, где видимый курсор заслонял бы заморозку). Стартует при `Bind` и при восстановлении чекпоинта.
  Настенный вопрос развилки управление не забирает — там таймер идёт.
  **WebGL (Demo b332, план b333 §2a):** после закрытия UI, экрана загрузки или возврата фокуса FPS-мост
  восстанавливает gaze, но взгляд выключен и курсор виден, пока браузер не подтвердит pointer lock по
  жесту игрока. Раньше таймер ждал это подтверждение, и ученик, который просто стоял, подсказки не получал
  никогда (в редакторе захват мгновенный, поэтому дефект был виден только в браузере). Ожидание браузера
  (видимый курсор и выключенный взгляд при включённом gaze, без заявок и с ходящим контроллером) — не
  занятость интерфейсом: таймер идёт. Регрессии: `RouteHintPresenceUseCaseTests` (Unit) и
  `WebGlRouteHintControlReturnPlayModeTests` (настоящий `Update` миникарты: возврат управления, вход в новую
  комнату и появление пунктира без жеста браузеру). Подтвердить на сессии владельца — по логу WebGL-билда.
- **Незавершённое интерактивное задание** — если в текущей комнате пути есть активный
  `IRoomTaskAnchor` с `IsTaskCompleted == false`, цель находится на доступном полу рядом с панелью.
  После завершения задания или в обычной комнате цель — дверь ближайшей следующей непосещённой
  комнаты критического пути. Состояние двери само по себе не определяет завершённость задания.
- **Линия** — `PlanRouteHintPathUseCase`: Дейкстра по доступным дверям между раскрытыми комнатами;
  запертая дверь не может быть транзитом. Внутри комнаты маршрут проверяет непрерывное покрытие
  пола и мировые сегменты стен из кэша миникарты. Подтверждённый сокет связи вырезает узкий проём,
  даже если bounds декоративной стены захватил дверной проём. Для обхода внутренних перегородок
  используется граф видимости центров ячеек и концов внутренних стен; его постоянная часть и
  пути между дверями кэшируются на уровень. Ячейки authored комнат сдвигаются на
  `RoomTemplate.PlacementBoundsMinX/ZMeters`: этот же снимок пола рисует заливку карты.
  Подтверждённому сокету разрешён короткий выход за край footprint, остальному маршруту — нет.
  Маршрут держит зазор от сегментов стен; точки обхода концов стен учитывают тот же зазор.
  Если игрок стоит у стены, первые 0,75 м маршрута выходят к безопасному зазору с минимальным
  допуском у стартовой точки; остальная линия сохраняет полный зазор. Сплошная стена остаётся
  непроходимой и при таком старте.
  У подтверждённой двери зазор уменьшается только возле проёма, чтобы узкая дверь оставалась
  достижимой даже при широком сегменте стены.
  Ширина подтверждённого проёма берётся из реальной дверной рамы, поэтому толстый рендерер стены
  не перекрывает проход. При отрисовке радиус точек и толщина линии ограничиваются доступным местом
  между стенами в текущем масштабе карты; участки без видимого зазора пропускаются.
  Если безопасного пути нет, результат `Unreachable`, линия не рисуется.
  Если точка настенной панели попала в сегмент стены, цель переносится на ближайший достижимый пол
  рядом с панелью, со стороны игрока; прямое наведение через стену не допускается.
  Нераскрытые комнаты не участвуют: линия заканчивается на двери, а не внутри скрытой комнаты.
  Путь проверяется раз в `RouteHintReplanIntervalSeconds` (0.25 с) и пересчитывается при смене цели,
  раскрытии комнаты, блокировке транзитной двери или потере безопасного отрезка. При обычном движении
  линия обновляет первую точку и убирает уже пройденные углы, проверяя каждый сокращённый отрезок
  теми же стенами. После недостижимой цели повторная попытка откладывается минимум на 2 секунды,
  чтобы поиск не перегружал WebGL. Если первый отрезок пересёк стену, линия скрывается.
- **Отрисовка** — `LevelMinimapController.RouteHint.cs`, живым слоем поверх кэша геометрии (под
  маркером выхода, колбами и игроком), только на `Repaint`, с общей для всех живых слоёв проекцией.
  Точки — один `GUI.DrawTexture` на точку из процедурного спрайта, в который запечены заливка и кант
  (перезапекается при смене цветов в настройках); не больше 160 точек на карту, невидимые отсекаются
  по пересечению с рамкой. Появление: плавная прозрачность и «прорисовка» от игрока к цели;
  вход в комнату вне пути или открытие двери показанную подсказку не гасят, таймер идёт дальше.
- Готового решения для пунктира в проекте нет: миникарта — IMGUI, штатный UI Toolkit `Painter2D` в
  `OnGUI` не рисует, а в `Assets/` и подключённых пакетах пунктирных/линейных рисовальщиков нет.
  Поэтому подсказка переиспользует уже существующие примитивы контроллера (`DrawLine`, клип по карточке).
  Нет GL-шейдера `Hidden/Internal-Colored` или `SetPass` отказал — стены карты пустые, а в лог уходит одно
  предупреждение вместо исключения в каждом `OnGUI` (раньше такое исключение опустошало обе карты).
- **Большая карта (`M`)** рисуется только пока ученик в мире (`IsFullMapVisible`): IMGUI лежит поверх любой
  панели UI Toolkit, и открытая карта иначе закрывала бы чат, код-станцию или вопрос голубой рамкой посреди
   экрана. На время панелей открытая карта прячется и возвращается вместе с управлением;
  `M` в это время не действует. Открытие читом при открытой чит-панели покажет карту после её закрытия.
  Почему большая карта бывает пустой в браузере, пока не найдено (§2a открыт): первая отрисовка после
  открытия пишет `Full map first draw: geometry=… textureCreated=… rooms=… projection=… fit=…` и, если карта
  пустая, первую причину — слишком маленький прямоугольник, нет GL-материала, текстура кэша не создана, нет
  раскрытых комнат или не легла проекция (без проекции не рисуются ни пунктир, ни игрок).
  Хвост `fit=center(…) size=… top=<комната>:<дальность>,…` называет вписанный прямоугольник и две самые
  дальние от его центра комнаты: сразу видно, что раздуло охват и сделало рисунок мелким.
- Если подсказку показать нельзя (нет пути до выхода, нет геометрии, недостижимо, игрок вне
  комнат), контроллер пишет одно `LevelGenerationRuntimeLog.Warn` на смену исхода и цели.
- **Диагностика в WebGL-сборке** (консоль браузера / player log). Одна строка на смену состояния:
  `Route hint state changed: idle=… presence=… first=… outcome=… planned=… path=… floor=… alpha=…
  liveStartBlocked=… fullMap=… focused=… cursor=… room=…`. Что искать, если пунктира нет:
   `presence=Occupied` и `first=` — какая заявка или состояние держит ученика (раньше в WebGL здесь стоял
   `CursorVisible`/`LookDisabled`); `outcome=Waiting` при растущем `idle` — подсказка ещё не должна быть;
   `Route hint idle timer restarted (…)` — только прогресс: вход дальше по пути (`route progress in …`)
   или выполненное задание цели (`target task in … completed`); частые сбросы от боковых комнат и дверей
   были дефектом и убраны; `planned=False` и
  `Route hint unavailable: <исход>, … cause: <причина>` — прокладка пути не удалась, и причина названа
   (`PlanRouteHintPathUseCase.Diagnose`: ученик далеко от пола, нет цепочки открытых дверей, ученик зажат
   стенами, стены внутри комнаты не оставляют пути); строка пишется один раз на смену причины, а не на каждую
   попытку, и та же `cause=` стоит в `RouteHintDiagnosticText` чит-панели; `trailDev=` — на сколько метров
   ученик отошёл от общей линии; `liveStartBlocked` теперь всегда `False`: начало линии не зависит от того,
   где стоит ученик; `floor=FloorRevealing` без перехода в
   `FloorHolding` — лента на полу не доиграла; терминального угасания ленты по времени нет: пока подсказка
   нужна, фаза остаётся `FloorHolding`; `Route hint floor ribbon: <причина>` — почему ленты нет
   (нет префаба, нет материала, вырожденный путь, слишком сложный путь, путь не готов — повтор),
   а `Route hint floor ribbon shown: points=… verts=… tris=… length=… center=… player=…` — что построилось
   и где лежит в момент начала показа. Про голубую рамку: `Full map opened by key M|cheat
  …` и `Full map first draw: …` (см. выше). Прежняя периодическая строка при блокировке дольше 20 с сохранена.
- Чит (раздел генерации уровней): «показать сразу, без ожидания простоя» (`SetRouteHintForced`;
  запоминается, только если есть активный уровень, и применяется к миникарте каждого нового уровня —
  новый уровень сам принудительный показ сбрасывает) и «сбросить таймер простоя».

### Путь подсказки на полу

Подсказка сначала проявляется цепочкой золотых звёздочек над полом, затем включается прежний
пунктир миникарты. Вид уточнён владельцем 2026-10-16 (план b333 §2b): «золотой след» Genshin,
маленькие светящиеся четырёхлучевые искры, без стрелок и сплошной полосы.

Префаб `Assets/_source/Prefabs/RouteHint/RouteHintFloorView.prefab` назначен в
`Resources/Minimap/LevelMinimapSettings.asset`. Материал `RouteHintSparkles.mat` использует готовую
`Epic Toon FX/Textures/sparkle2.png`: мягкая четырёхлучевая звезда, новая текстура не нужна.
Подложка и свечение пола убраны полностью: отдельные искры оставляют видимым рисунок пола.
Страж `RouteHintFloorPrefabGuardTests` проверяет поставку материала и текстуры звёзд;
`RouteHintFloorViewTests` и PlayMode проверяют отсутствие полосы.

- **Один путь на двоих.** Звёзды на полу и пунктир миникарты рисуют ОДНУ линию — `RouteHintTrail`
  (`Runtime/Application`): сглаженная полилиния мировых XZ из `PlanRouteHintPathUseCase`, углы скруглены один
  раз (`RouteHintTrailBuilder`, радиус `routeHintFloorCornerRadiusMeters`, допуск отхода
  `routeHintFloorCornerMaxDeviationMeters` — 0,25 м, шаг точек `routeHintFloorSampleSpacingMeters`), к каждой точке
  приложена свободная ширина до стен (`Clearances`). Линия заменяется только при перепланировании
  (`Revision`); между ними двигается лишь видимое начало (`HeadDistance`/`HeadPoint`) — по тем же точкам.
  Миникарта проецирует `[HeadPoint] + точки за ним` (`FillVisible`), вьюшка пола получает те же точки без
  пересглаживания и пересэмплирования (`RouteHintRibbonMeshBuilder.BuildFromAxis` лишь добавляет высоту
  пола под каждой точкой). Контроллер отдаёт линию как `RouteHintTrail`; `RouteHintWorldPath` и
  `RouteHintFloorPolyline` — её точки. Решение «когда» — прежнее (`LevelRouteHintSession`).
- **Путь не жмётся к стенам.** `RouteHintPathOptions` (из SO: `routeHintPathWallClearanceMeters` 0,9 м плюс
  допуск скругления, чтобы скругление не съело отступ; `routeHintPathDoorApproachMeters` 1,4 м) включают в
  планировщике режим отступа: внутри комнаты маршрут ищется по графу видимости с узлами в центре и
  четвертях каждой ячейки пола и у концов перегородок, а отрезок допускается, только если он держит отступ
  от поверхности каждой стены; дверной проём проходится по центру точкой подхода прямо перед дверью по
  перпендикуляру к стене (направление стены запоминается при регистрации проёма). Где комната уже отступа,
  он ступенчато уменьшается (полный, 3/4, чуть больше половины), затем работает прежний поиск с отступом
  0,45 м — маршрут не теряется. Нулевой отступ — прежний планировщик без изменений.
- **Игрок в проёме.** Игрок, стоящий в дверном проёме (на несколько дециметров за краем пола своей
  комнаты), раньше получал `Unreachable` навсегда (пол под ногами не принадлежал ни одной комнате, первый
  отрезок не проходил проверку пола). Теперь старт — ближайшая точка пола раскрытой комнаты в пределах
  `StartSnapMeters` (1,2 м), а если у игрока нет ни одного свободного первого шага (проём между косяками, ниша),
  пробуются точки на кольцах 0,4–1,6 м вокруг, до которых можно дойти, не задев стену. Закрытая, но не
  запертая дверь проходима; запертая или выключенная по-прежнему стена.
- **Начало впереди игрока и следование.** Видимая часть начинается на `routeHintPathStartOffsetMeters`
  (0,75 м) впереди проекции игрока на линию, вдоль пути; у цели всегда остаются видны
  `routeHintPathMinVisibleMeters` (0,5 м). Пока игрок в пределах `routeHintReplanDeviationMeters` (1,5 м) от
  линии, она только тянет за ним своё начало (каждый кадр, без аллокаций и без планировщика). Дальше — перепланирование
  от игрока (`DecideRouteHintReplanUseCase`), не чаще `routeHintReplanIntervalSeconds` (0,25 с); смена цели,
  раскрытие комнат, задания или набора запертых дверей перепланирует сразу. Вьюшка пола при перепланировании
  берёт новые точки без перезапуска проявления и часов (`UpdatePath`), высоту пола зондирует один раз на
  перепланирование, а не каждый кадр.
- **Путь идёт сквозь целевую дверь** (владелец 2026-10-16). Маршрут к двери следующей комнаты не обрывается
  в проёме: `RouteHintPathOptions.DoorLeadOutMeters` (`routeHintPathDoorLeadOutMeters`, 2 м; 0 — прежнее
  поведение) продолжает его прямо по направлению подхода в следующую комнату. Отрезок обрезается по полу и
  стенам той комнаты (шаги 1 / 0,75 / 0,5 / 0,3 длины, не короче 0,5 м), а при отсутствии места путь просто
  кончается у двери. Раскрытая карта не выдаётся: отдаётся только короткий прямой отрезок, не раскладка комнаты.
- **Линия плывёт, а не прыгает.** Когда ученик ушёл от линии дальше `routeHintReplanDeviationMeters` и путь
  построился заново (мир тот же), `RouteHintTrail.AssignBlended` оставляет на экране старую линию и за
  `routeHintReplanBlendSeconds` (0,35 с) перетекает её в новую (`AdvanceBlend` каждый кадр; точки сопоставляются
  по остатку пути до общей двери). Другой маршрут (длина отличается больше чем на 2,5 м), первый путь, смена
  цели, раскрытие комнат и заданий — прежняя мгновенная замена.
- **Подсказка держится, пока ученик идёт по ней.** Ходьба к цели больше не гасит ленту
  (`routeHintFloorApproachMeters` = 0, `RouteHintRevealTiming.ApproachMeters` по умолчанию 0). Подсказка уходит,
  только когда решение о ней снято: прогресс (вход в комнату критического пути дальше всех посещённых или
  выполнение задания цели — `DecideRouteHintProgressUseCase`, тот же прогресс, что сбрасывает таймер простоя)
  или занятость интерфейсом. Боковая комната и неверная ветка не прогресс: подсказка остаётся, путь
  перепланируется от ученика.
- **Высота пола** — луч вниз (`Runtime/Infrastructure/RouteHintFloorRaycastProbe`, адаптер физики: слои
  `routeHintFloorLayers`, мимо триггеров и коллайдеров игрока; до 16 попаданий в буфере, сортировка по
  расстоянию, при заполненном буфере — повтор через `RaycastAll`, чтобы пол не потерялся) с
  `routeHintFloorProbeHeightMeters` (1,2 м) над ПРЕДЫДУЩЕЙ принятой точкой; решение —
  `ResolveRouteHintFloorHeightUseCase`: попадание дальше `routeHintFloorMaxStepMeters` от предыдущей точки —
  декор (ящик, стол), линия остаётся на прежней высоте; лестница и пандус проходят ступенька за ступенькой.
  Линия приподнята на `routeHintFloorLiftMeters`. `RouteHintFloorView` берёт только `Centerline` и
  `CenterlineDistances`: меш не загружается и не рисуется. `RouteHintRibbonMeshBuilder.Build` (со своим
  скруглением) сохранён для прочих потребителей; жёсткий потолок точек `HardMaxSamples`
  (`RouteHintRibbonFailure.TooComplex`) действует и для общей линии: слишком сложный путь — звёзд нет,
  пунктир показывается сразу.
- **Вид и движение** — `RouteHintStarField` (чистая функция линии и часов; всё из SO). Shuriken с аддитивным
  материалом и золотисто-жёлтым HDR-цветом (`routeHintFloorSparkleColor`, 2,2/1,65/0,12; тот же цвет в
  материале). Густой поток: шаг `routeHintFloorSparkleSpacingMeters` — 0,1 м (10 искр/м); решётка слотов
  привязана к расстоянию по линии и дрейфует к цели со средней скоростью
  `routeHintFloorSparkleSpeedMetersPerSecond` — 0,5 м/с; у каждой звезды своя качка вдоль пути
  (`routeHintFloorSparkleAlongWobbleMeters`, период `…WobbleSeconds` со спредом 0,6–1,4) и вбок
  (`…LateralWobbleMeters`) — собственная вариация скорости и направления. Размер:
  `routeHintFloorSparkleSizeMeters` × от `…SizeMinScale` (0,5) до `…SizeMaxScale` (2) с перекосом
  `…SizeSkew` (3): большинство мелкие, несколько крупных. Мерцание: быстрое `…TwinkleHertz` со спредом
  `…TwinkleHertzSpread`, а доля `…LongTwinkleFraction` (20%) мерцает долго и глубоко — период
  `…LongTwinkleSeconds` (3,5 с), глубина `…LongTwinkleDepth`; длительность мерцания звезды — её
  `startLifetime`. Боковой разброс ±`…LateralJitterMeters` плюс качка не больше 0,3 м и дополнительно зажат
  свободной шириной вдоль линии минус `…WallMarginMeters`: звёзды не ложатся на стены, на поворотах и в
  дверях тоже. Высота 0,175±0,125 м над найденным полом. Видимая часть начинается у головы линии и
  проявляется там плавно (`routeHintFloorStartFadeMeters`), у цели гаснет; фронт проявления открывает уже
  заполненную цепочку. Бюджет `routeHintFloorMaxSparkles` — **400 частиц** по умолчанию, защитный предел —
  **512**; на пути длиннее 40 м поток реже, но охватывает весь путь. Стоимость WebGL: один ParticleSystem,
  один материал, один проход шейдера, до 400 билбордов; время кадра ещё не измерено. Позиции считаются по
  scaled clock в заранее выделенном массиве и передаются через `SetParticles`; в `Render` нет выделений
  памяти. Автономная симуляция выключена (`simulationSpeed=0`, `useUnscaledTime=false`). VFX Graph не
  используется. Шейдер `RedoSchool/LevelGeneration/RouteHintFloorStars` хранится по историческому пути
  `Runtime/Shaders/RouteHintFloorRibbon.shader`, сохраняя GUID; в нём только текстура звезды, цвет
  материала и цвет частицы. Старый MeshRenderer префаба выключен.
- **Порядок** — `DecideRouteHintRevealUseCase` (состояние — `RouteHintRevealTimeline`): лента проявляется за
  `routeHintFloorRevealSeconds` (1,25 с) → держится весь срок подсказки, тот же, что у пунктира на миникарте
  → гаснет, только когда подсказка больше не нужна (прогресс, конец маршрута, панель). Пунктир на миникарте
  включается, когда проявление на полу закончилось, и остаётся, пока подсказка нужна. Подсказка ушла — лента
  гаснет за `routeHintFloorHideFadeSeconds`, при следующем показе проявляется снова. Пустой путь в момент
  начала показа — повтор на следующем кадре, а не отказ. Выключенная миникарта (`OnDisable`,
  `SetOverlayVisible(false)`) гасит ленту. Проявление и звёздочки идут по игровому времени; исключение —
  подсказка больше не нужна (`visible=false`, включая занятность интерфейсом): лента и пунктир гаснут по
  **unscaled time** за `routeHintFloorHideFadeSeconds` (0,18 с), даже при `timeScale=0`. По завершении
  контроллер вызывает `Hide()`: лента выключена, все звёздочки остановлены и очищены. Простой для решения
  копится по игровому времени.
- **Без ленты** (`routeHintFloorEnabled = false`, префаб не назначен, нет материала, лента по этому пути не
  построилась — до смены цели, редакторские тесты вне Play Mode) пунктир на миникарте появляется сразу —
  прежнее поведение; причина пишется одной строкой на уровень. Экземпляр ленты создаётся дочерним к
  контроллеру миникарты при первом показе и уничтожается вместе с уровнем; тесты и стенды подставляют
  вьюшку через `SetRouteHintFloorView`.

Все параметры — `LevelMinimapSettings` (`Runtime/Resources/Minimap/LevelMinimapSettings.asset`,
меню `Create → Neoxider → LevelGeneration → Minimap Settings`); поле `settings` у контроллера
позволяет подменить ассет явно, без ассета действуют те же значения по умолчанию.
